# Архитектура Abak.IDE & CODESYS V3.5 Bridge

## 1. Введение
CODESYS V3.5 и специализированные среды на его основе (включая Abak.IDE для контроллеров АБАК) исторически создавались как закрытые настольные Windows-приложения. Хотя среда включает встроенный интерпретатор IronPython (**ScriptEngine**), стандартный способ его запуска ограничен пакетным режимом командной строки (`codesys.exe --runscript=...`), который:
1. Запускает новый экземпляр IDE (требует 30–60 секунд).
2. Полностью закрывает IDE после выполнения скрипта.
3. Не позволяет работать с проектом интерактивно, когда инженер или оператор держит проект открытым на экране.

Архитектура **`abak-ide-bridge`** кардинально решает эту проблему, превращая запущенный экземпляр Abak.IDE в **управляемый по сети сервер автоматизации** без потери отзывчивости пользовательского интерфейса.

---

## 2. Потоковая модель и интеграция с GUI

### Проблема блокировки UI
Интерфейс CODESYS V3.5 построен на базе Windows Forms / WPF. Если в IronPython запустить бесконечный цикл:
```python
# ОШИБКА: Замораживает весь интерфейс Abak.IDE!
while True:
    client, addr = sock.accept()
    handle(client)
```
поток GUI перестает обрабатывать события Windows (`WM_PAINT`, клики мыши, клавиатурный ввод), и IDE зависает со статусом *"Не отвечает"*.

### Решение: WinForms Timer Pump
Сервер моста использует стандартный компонент `.NET System.Windows.Forms.Timer`:
```python
bridge_timer = Timer()
bridge_timer.Interval = 100 # Опрос каждые 100 мс в UI потоке
bridge_timer.Tick += on_timer_tick
bridge_timer.Start()
```
На каждом тике таймера:
1. Вызывается `active_listener.Pending()` (неблокирующая проверка наличия входящего TCP-соединения).
2. Если соединений нет, метод мгновенно завершается ($< 0.1\text{ мс}$), возвращая управление циклу отрисовки Windows Forms.
3. Если соединение есть — запрос считывается, выполняется диспетчеризация действия в контексте активного проекта, и результат возвращается клиенту.

Поскольку все действия выполняются **в главном UI-потоке**, они имеют прямой и легальный доступ ко всей объектной модели CODESYS (`projects.primary`, `system`, `online`, компилятор), исключая исключения `CrossThreadMessagingException`.

## 3. Сетевой протокол HTTP/JSON

Сервер реализует легковесный протокол поверх сырых сокетов .NET (`System.Net.Sockets.TcpListener`):
- **Транспорт**: TCP порт `11888` (автоматический перебор `11889, 11890, 12888` при занятости).
- **Формат сообщений**: HTTP/1.1 `POST` или `GET` с `Content-Type: application/json; charset=utf-8`.
- **Защита от сбоев сокета**: флаг `ReuseAddress` в .NET на Windows не используется во избежание ошибки `WSAEACCES` (`Errno 22`).

## 4. Объектная модель CODESYS ScriptEngine

Сервер оперирует следующими ключевыми интерфейсами:
1. `projects.primary`: активный открытый проект (`ScriptProject`).
2. `app = proj.find('Application', True)[0]`: узел логики контроллера.
   - `app.build()`: запуск инкрементальной компиляции.
   - `app.clean()`: очистка скомпилированных артефактов.
   - `app.find(name, recursive)`: поиск POU, DUT, GVL.
3. `ScriptObject`:
   - `obj.textual_declaration`: интерфейс редактирования заголовка POU/типа (`.replace(st_text)`).
   - `obj.textual_implementation`: интерфейс редактирования тела программы (`.replace(st_text)`).
   - `obj.remove()`: удаление узла из дерева.
4. `ScriptDeviceObject` (Устройства и каналы I/O):
   - `mod.connectors[0].host_parameters`: перечень аппаратных каналов модуля.
   - `p.is_mappable_io`: флаг возможности привязки.
   - `p.io_mapping.variable`: имя переменной для привязки (`Application.GVL.myVar`).
   - `con.io_always_mapping = True`: флаг принудительного опроса шины.

## 5. Графический кэш редактора (AST vs GUI Buffer)
Важная архитектурная особенность CODESYS:
- Метод `textual_implementation.replace(...)` перезаписывает AST и сериализованный объект в базе данных проекта (`.project`).
- Однако если POU **уже был открыт во вкладке графического редактора** пользователем, внутренний буфер текстового контрола не слушает внешние изменения объекта.
- **Правило работы**: при обновлении кода через мост необходимо закрыть вкладку программы крестиком (без сохранения) и открыть заново из дерева проекта.
