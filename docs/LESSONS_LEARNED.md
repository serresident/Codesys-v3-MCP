# Практические уроки, грабли и решения (Lessons Learned)

В ходе разработки и боевого применения сетевого моста к Abak.IDE был накоплен уникальный опыт по взаимодействию IronPython 2.7, .NET Framework и ядра CODESYS V3.5. Ниже приведены ключевые проблемы и их готовые решения.

---

## 1. Ошибка сокета: WSAEACCES / [Errno 22] при ReuseAddress
- **Симптом**: при попытке привязать сокет с `socket.SO_REUSEADDR` или свойством .NET сокета `ExclusiveAddressUse = False` сервер падал с ошибкой:  
  `[Errno 22] Сделана попытка доступа к сокету методом, запрещенным правами доступа`.
- **Причина**: в Windows по умолчанию стандартный пользователь без прав администратора не может захватывать сокеты с флагом совместного использования, если порт уже был зарезервирован или закрывается.
- **Решение**:
  - Использовать `TcpListener(IPAddress.Any, port)` напрямую без принудительного `ReuseAddress`.
  - Реализовать список резервных портов (`[11888, 11889, 11890, 12888]`) с автоматическим перебором.
  - Перед созданием нового слушателя явно вызывать `.Stop()` у предыдущего сохраненного экземпляра.

---

## 2. Несоответствие типов: IronPython `bytearray` vs .NET `Byte[]`
- **Симптом**: при вызове `stream.Read(buffer, 0, len)` в IronPython возникал `TypeError: expected Array[Byte], got bytearray`.
- **Причина**: динамические типы Python (`str`, `bytearray`) не маршалируются автоматически в фиксированный типизированный массив .NET `System.Byte[]`.
- **Решение**:
  - Побайтовое чтение потока через `stream.ReadByte()`, где результат — целое число (`Int32`), которое легко конвертируется через `chr(b)`.
  - Для записи ответа в сокет — использование нативного метода кодирования .NET:
    ```python
    hdr_bytes = System.Text.Encoding.UTF8.GetBytes(http_header)
    stream.Write(hdr_bytes, 0, hdr_bytes.Length)
    ```

## 3. Открытые вкладки в редакторе Abak.IDE
- **Симптом**: скрипт заменил текст реализации POU через `obj.textual_implementation.replace(...)`, вызов `exec` показывает новый код, но инженер видит в окне Abak.IDE старый код.
- **Причина**: текстовый редактор CODESYS кэширует документ в оперативной памяти окна. Если пользователь в этот момент нажмет `Ctrl+S`, старый текст из окна перезапишет новый код в базе данных.
- **Решение**:
  - Всегда уведомлять пользователя: *"Закройте вкладку крестиком без сохранения и откройте заново из дерева"*.

---

## 4. Ошибки при создании DUT через ScriptEngine
- **Симптом**: при вызове `parent.create_dut('CLIENT_STATE', script_engine.DutType.Enumeration, text)` CODESYS обернул переданный код во внутренний шаблон `(enum_member := 0)`, что привело к синтаксической ошибке компилятора `C0077: Неизвестный тип: 'CLIENT_STATE'`.
- **Решение**:
  - После создания DUT всегда вызывать `obj.textual_declaration.replace(...)`, передавая чистый, полный текст объявления от `{attribute ...}` до `END_TYPE`.

---

## 5. Запрет на удаление системных задач Task Configuration
- **Симптом**: вызов `task.remove()` на объектах задач в `Task Configuration` приводил к `NullReferenceException / Ссылка на объект не указывает на экземпляр объекта`.
- **Причина**: менеджер задач CODESYS управляет коллекцией задач через собственный внутренний провайдер; прямое удаление через интерфейс дерева узлов блокируется ядром.
- **Решение**:
  - Удалять вызовы POU внутри задач (`task_child.remove()`), но не сам системный узел задачи, либо переназначать вызовы.

---

## 6. Длина строк и кодировки в PowerShell 5.1
- **Симптом**: при вызове CLI скриптов из PowerShell 5.1 русские символы в выводе логов или стрелки (`→`) приводили к `UnicodeEncodeError: 'charmap' codec can't encode character`.
- **Решение**:
  - Перед запуском Python в PowerShell всегда задавать переменные окружения:
    `$env:PYTHONIOENCODING="utf-8"; [Console]::OutputEncoding = [System.Text.Encoding]::UTF8`.


## 7. Модули Modbus IO Mapping и несовпадение типов (Типы канала и переменной не совпадают)
- **Симптом**: При привязке переменной через `p.io_mapping.variable = 'Application.GVL.MyVar'` компилятор выдает ошибку: `Типы канала и соотнесённой переменной не совпадают`.
- **Причина**: В CoDeSys 3.5 драйвер Modbus TCP/RTU строго требует, чтобы размер привязываемой переменной в байтах досконально соответствовал настроенной длине (Length) канала, иначе возникает конфликт типов.
- **Решение**:
  - Для **FC1/FC2 (Дискретные входы/Coils)**: Канал должен быть соотнесен с массивом `ARRAY[0..N-1] OF BOOL`, где `N` — точное количество битов (настроенная длина).
    - Пример: Длина канала 20 битов $\to$ `ARRAY[0..19] OF BOOL`.
  - Для **FC3/FC4 (Регистры Holding/Input)**:
    - Длина 1 регистр: Соотносить с простым типом `WORD` (или `INT`, `UINT`).
    - Длина 2 регистра: Соотносить с `DWORD` или `REAL` (32-битные типы). Если привязать к `ARRAY[0..1] OF WORD`, может возникнуть конфликт, так как 2-словные регистры драйвер часто оптимизирует.
    - Длина N регистров (N > 2): Соотносить строго с `ARRAY[0..N-1] OF WORD`.
  - Внимание: Свойство `p.io_mapping.mapping_creates_variable` в ScriptEngine API является **Read-Only** (возвращает `AttributeError: can't assign to read-only property`), поэтому невозможно заставить скрипт 'автоматически создать переменную' в глобальном пространстве. Переменная должна быть уже корректно объявлена в ST-коде (например, в GVL) перед её привязкой.

## 8. Использование f-strings (f"...") в IronPython 2.7
- **Симптом**: При попытке выполнить скрипт через `abak_exec_python` (Action: `exec`) сервер возвращает `SyntaxError: invalid syntax`.
- **Причина**: Встроенный в Abak.IDE интерпретатор `IronPython` имеет версию 2.7. Строковые интерполяции f-strings (появившиеся в Python 3.6) в нем не поддерживаются.
- **Решение**: Использовать классическую конкатенацию `"string" + str(val)` или `"{0}".format(val)`.

## 9. Блокировка (Зависание) ScriptEngine при Online Login (Стек пуст)
- **Симптом**: При попытке программно загрузить проект в ПЛК через `online_app.login(1, True)` скрипт выполняется минуту и падает с ошибкой `Стек пуст` (Stack Empty).
- **Причина**: Вызов `login` с флагом Download пытается открыть всплывающее UI-окно для подтверждения загрузки, если конфигурация отличается, или если шлюз (Gateway) физически недоступен. Поскольку вызов выполняется из фонового потока, диалог блокируется и выбрасывает внутренний таймаут/исключение.
- **Решение**: Выполнять подключение только через встроенный UI Abak.IDE (Alt+F8 / кнопка Логин), если ПЛК оффлайн или требует ручного подтверждения загрузки.

## 10. Получение списка ошибок компиляции (Build Errors)
- **Симптом**: Вызов `app.build()` возвращает объект `ScriptObject` или `True/False`, но не выводит текст ошибок.
- **Решение**: Ошибки находятся в системном Message View. Их можно получить так:
  ```python
  app.build()
  msgs = script_engine.system.get_messages()
  errors = [str(m) for m in msgs if 'ERROR' in str(m).upper() or 'WARNING' in str(m).upper()]
  ```


## 11. Разделение зон ответственности: XML Import vs ScriptEngine
- **Симптом**: ИИ-агенты тратят много времени и контекста на написание сложных Python-скриптов для замены кода внутри POU или GVL (через `obj.textual_declaration.replace`). Это приводит к ошибкам кэширования в IDE и сложности отладки.
- **Причина**: "Туннельное зрение". Из-за того, что привязку IO (IO Mapping) и работу с деревом устройств **невозможно** полноценно делать через импорт/экспорт PLCOpen XML, агенты по инерции продолжают использовать ScriptEngine и для редактирования логики.
- **Решение (Золотой стандарт Workflow)**:
  - **Для программной логики (POU, GVL, DUT, Task Configuration)**: ВСЕГДА использовать штатный механизм PLCOpen XML. Экспортировать исходники через `abak_export_sources`, редактировать обычные текстовые `.st` файлы локально, а затем импортировать обратно через `abak_import_plcopen_xml`.
  - **Для аппаратной части (Добавление устройств, Modbus, IO Mapping)**: Использовать `abak_exec_python` и ScriptEngine, так как аппаратная конфигурация CoDeSys не покрывается полностью стандартом PLCOpen XML.


## 12. Быстрый отказ (Fast-Fail) и конкурентный опрос портов
- **Симптом**: При сетевой работе с соседней инженерной станцией клиент зависал на 75–150 секунд, если Abak.IDE закрыта или заблокирована файрволом Windows.
- **Причина**: Брандмауэр Windows в корпоративных сетях часто сбрасывает входящие SYN-пакеты (SYN Drop) вместо возврата быстрого TCP RST. Последовательный перебор 5 портов с таймаутом 15–30 с давал суммарную задержку в 1.5–2.5 минуты.
- **Решение**: Внедрение в `common/transport.py` двухступенчатого адаптивного опроса:
  1. Оптимистичная быстрая проверка кэшированного порта (150 мс локально, 400 мс в LAN).
  2. При его недоступности — параллельный `ThreadPoolExecutor` по всем портам `[11888, 11889, 11890, 11891, 12888]` с жестким общим дедлайном в 1.5 секунды. Время реакции при оффлайн-сервере упало до **0.78 секунды**.

## 13. Автоматический запуск среды с мостом (Флаг `--runscript`)
- **Симптом**: Необходимость каждый раз вручную открывать меню `Инструменты -> Скрипты -> Выполнить скрипт`.
- **Решение**: Использование официального ключа запуска среды:
  `abak.ide.exe --profile="Abak.IDE V1.0.0.0" "MyProject.project" --runscript="server/codesys_bridge_server.py"`
  Это встроено в кнопку «💻 Открыть проект» в GUI Manager, в CLI-команду `python abak_bridge_client.py launch` и в пакетный файл `server/start_with_project.bat`.

## 14. Структурированный возврат данных через переменную `result`
- **Симптом**: Раньше результаты работы произвольных скриптов можно было получить только через перехват текста `print(...)`, что требовало хрупкого регулярного парсинга в клиенте.
- **Причина**: В классическом ScriptEngine вызов `exec` разделял глобальное пространство, но не возвращал структурированные объекты.
- **Решение**: По опыту `codesys-api` (Johannes Pettersson), сервер моста инициализирует в области видимости переменную `result = None` и пробрасывает словарь `params`. Если скрипт присваивает `result = {"status": "ok", "tags": 120}`, сервер автоматически возвращает этот словарь в JSON-ответе в поле `"result"`.
