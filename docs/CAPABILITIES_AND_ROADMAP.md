# Возможности системы и план развития (Capabilities & Roadmap)
**Abak.IDE & CODESYS V3.5 Automation Bridge**

Документ обобщает текущие реализованные возможности комплекса, архитектурные решения, а также результаты глубокого анализа внешних репозиториев (`codesys-api`, `codesys-mcp-toolkit`) и исторических наработок проекта с планом приоритетных улучшений.

## 2. Матрица текущих реализованных возможностей

### 2.1. Управление исходным кодом и объектами проекта
| Возможность | Описание | Поддерживаемые интерфейсы |
|---|---|---|
| **Двусторонняя декомпозиция ST** | Экспорт и импорт POU, GVL, DUT, Method, Action в отдельные `.st` файлы с секциями `// @DECLARATION` и `// @IMPLEMENTATION`. | MCP, CLI, GUI, API |
| **Сохранение GUID объектов** | Автоматическое извлечение и сохранение GUID через заголовок `// @OBJECT_ID: <guid>`, предотвращающее дублирование при повторном импорте. | MCP, CLI, GUI, API |
| **Рекурсивное автосоздание папок и POU** | При импорте несуществующие папки и POU создаются на лету (`create_pou`, `find_or_create_folder_path`). | MCP, CLI, GUI, API |
| **Стандартный экспорт PLCopen XML** | Полная выгрузка проекта в стандартизированный формат PLCopen XML с параметром `declarations_as_plaintext=True`. | MCP, CLI, GUI, API |
| **Импорт PLCopen XML** | Бесшовный импорт XML-спецификаций в активный проект без потери структуры. | MCP, CLI, GUI, API |
| **Автосохранение контекста** | Автоматическое сохранение `project_sources.xml` в папку `.context` для непрерывного контекста ИИ-ассистентов. | GUI, CLI, Server |

### 2.2. Сборка, сохранение и диагностика
| Возможность | Описание | Поддерживаемые интерфейсы |
|---|---|---|
| **Сборка проекта (`compile`)** | Компиляция активного приложения (`app.build()`). | MCP, CLI, GUI, API |
| **Чистая сборка (`Clean & Build`)** | Предварительная очистка кэша компиляции (`app.clean()`) перед пересборкой. | MCP, CLI, GUI, API |
| **Детализация ошибок и варнингов** | Перехват объектов сообщений компилятора (`system.get_message_objects()`), подсчет `errors_count`, `warnings_count`, извлечение Severity и текста. | MCP, CLI, GUI, API |
| **Сохранение проекта (`save`)** | Программное сохранение `.project` на диске инженерной станции (`proj.save()`). | MCP, CLI, GUI, API |

### 2.3. Инспекция проекта и аппаратного дерева (Hardware)
| Возможность | Описание | Поддерживаемые интерфейсы |
|---|---|---|
| **Дерево объектов Application** | Рекурсивный обход дерева логики (POU, GVL, типы, перечисления). | MCP, CLI, GUI, API |
| **Аппаратное дерево (Device Tree)** | Обход физических устройств: контроллер, шины, корзины, модули ввода/вывода (AI, AO, DI, DO, счетчики). | MCP, CLI, GUI, API |
| **Инспекция параметров устройств** | Чтение параметров узлов (`device_parameter`), адресов каналов и метаданных конфигурации. | MCP, CLI, GUI, API |
| **Привязка каналов I/O (`map_io`)** | Программная привязка каналов модулей к переменным GVL (`io_mapping.variable`), поддержка флага `always_update`. | MCP, CLI, GUI, API |

### 2.4. Онлайн-управление и взаимодействие с ПЛК
| Возможность | Описание | Поддерживаемые интерфейсы |
|---|---|---|
| **Онлайн статус (`online_status`)** | Проверка подключения, состояния среды исполнения (RUN, STOP, HALT, UNKNOWN). | MCP, CLI, GUI, API |
| **Подключение к ПЛК (`online_login`)** | Подключение по сети через CODESYS Gateway с гибкой стратегией онлайн-изменений (`Try`, `Force`, `Keep`, `Never`). | MCP, CLI, GUI, API |
| **Отключение (`online_logout`)** | Корректный разрыв сессии связи с контроллером. | MCP, CLI, GUI, API |
| **Управление исполнением (`online_control`)** | Дистанционный пуск (`start`), остановка (`stop`), горячий сброс (`reset_warm`), холодный сброс (`reset_cold`). | MCP, CLI, GUI, API |
| **Чтение переменных (`online_read`)** | Чтение значений переменных реального времени по списку путей (например, `Application.PLC_PRG.iVal`). | MCP, CLI, GUI, API |
| **Запись и форсирование (`online_write`)** | Обычная запись (`write`) и принудительное форсирование значений (`force`). | MCP, CLI, GUI, API |

### 2.5. Выполнение произвольного кода (Script Runner)
| Возможность | Описание | Поддерживаемые интерфейсы |
|---|---|---|
| **Произвольный IronPython код** | Выполнение любого синтаксиса Python 2.7 / ScriptEngine с доступом ко всем сборкам .NET CLR (`System.*`). | MCP, CLI, GUI, API |
| **Запуск скрипта по пути (`script_path`)** | Исполнение существующего файла `.py` на инженерной станции без дублирования исходного текста в запросе. | MCP, CLI, API |
| **Передача параметров (`params`, `args`)** | Проброс словаря `params` и списка `args` прямо в область видимости скрипта. | MCP, CLI, API |
| **Структурированный возврат (`result = ...`)** | Скрипт может вернуть любой словарь или объект через присвоение `result = {...}`, который возвращается в ответе JSON (`response["result"]`). | MCP, CLI, GUI, API |
| **Встроенный Script Runner в GUI** | Вкладка с шаблонами (информация о проекте, дерево устройств, онлайн статус, JSON расчет), кнопками загрузки/сохранения `.py` и окном вывода результатов. | GUI |

### 2.6. Клиентские интерфейсы
- **FastMCP Сервер (`abak_mcp_server.py`)**: 13 готовых инструментов для ИИ (Antigravity, Cursor, Claude Desktop), поддержка автопереключения таймаутов и обработки сбоев связи.
- **Консольный CLI (`abak_bridge_client.py`)**: Полный набор подкоманд (`status`, `save`, `compile`, `inspect-tree`, `exec`, `map-io`, `export`, `import`, `export-xml`, `import-xml`, `online-*`).
- **Cyberpunk GUI (`gui_manager.py`)**: Темный неоновый стиль, асинхронный опрос статуса среды, вкладка логов, полноценная Git-панель (Diff, Commit, Push, Pull), вкладка запуска скриптов, справочный раздел.

## 4. План развития (Roadmap) на основе анализа

### Фаза 1. Управление конфигурацией проекта (Project & Task Management)
- [ ] **Library Manager API (Менеджер библиотек)**:
  - Действие `get_libraries`: список всех подключенных библиотек, версий, статуса разрешения зависимостей (Resolution).
  - Действие `add_library` / `remove_library`: программное подключение библиотек (например, системных драйверов протоколов, математических пакетов).
- [ ] **Task Configuration API (Управление задачами ПЛК)**:
  - Получение списка задач (`MainTask`, `BusTask`, `FastTask`): циклические интервалы (мс), приоритеты (0–31), тип вызова (Cyclic, Event, Freewheeling, External).
  - Программное добавление вызовов POU в список выполнения конкретной задачи (`task.add_pou_call(...)`).
- [ ] **Управление свойствами проекта (Project Information / Author Metadata)**:
  - Чтение и запись версии проекта, автора, описания, настроек целевого рантайма.

### Фаза 2. Управление топологией оборудования (Hardware & Bus Management)
- [ ] **Device Repository API (Репозиторий таргетов и дескрипторов)**:
  - Листинг установленных в среде Target-пакетов и описаний устройств (`device_repository`).
- [ ] **Программное добавление и замена устройств**:
  - `add_device(parent, device_type, id, name)`: программная вставка модулей расширения на шины (EtherCAT, Profinet, CANopen, встроенная шина корзины ПЛК).
  - `update_device`: обновление версии дескриптора или прошивки устройства при смене ревизии ПЛК.
- [ ] **Параметризация полевых шин (Bus Parameters)**:
  - Чтение и запись Baudrate, Node ID, интервалов Sync, адресов Modbus Slave.

### Фаза 3. Интерактивная отладка и диагностика рантайма (Debugging & Diagnostics)
- [ ] **Точки останова (Breakpoints API)**:
  - Установка точки останова на конкретную строку POU: `set_breakpoint(pou_name, line)`.
  - Снятие точек останова, проверка состояния срабатывания (`is_hit`).
- [ ] **Пошаговое выполнение (Step Debugging)**:
  - Команды `step_over`, `step_into`, `step_out` в режиме online.
- [ ] **Мониторинг времени цикла и загрузки CPU**:
  - Чтение системной статистики выполнения задач: минимальное, максимальное и среднее время цикла (Min/Max/Avg cycle time), дрожание (jitter).
- [ ] **CODESYS Trace Engine (Снятие трендов и осциллограмм)**:
  - Программное создание конфигурации Trace, добавление переменных для записи, запуск и выгрузка трендов в CSV / JSON.

### Фаза 4. Автоматизированное сквозное тестирование (CI/CD & Automated Testing)
- [ ] **Runner автоматических E2E тестов логики ПЛК**:
  - Сценарий: компиляция проекта -> загрузка в ПЛК / симулятор -> перевод в RUN -> эмуляция аварийных входов (Force I/O) -> проверка реакции выходов (Assert) -> генерация отчета в JUnit / Markdown.
- [ ] **Проверка качества кода (Static Analysis / Linter)**:
  - Статический анализ исходников ST на соответствие соглашениям именования (Hungarian notation, стандарты ПЛК), детектирование неиспользуемых переменных.

### Фаза 5. Безопасность и надежность моста
- [ ] **API-аутентификация (Bearer Token / API Key)**:
  - Поддержка авторизационного токена для защиты HTTP-порта 11888 при размещении моста в открытой сети предприятия.
- [ ] **Watchdog и автоперезапуск слушателя**:
  - Автоматическое восстановление сокета при сбоях сетевого адаптера или перезагрузке службы.
